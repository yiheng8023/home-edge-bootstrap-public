# 兼容性政策

[English](../COMPATIBILITY.md) · [首页](../../README.zh-CN.md)

兼容性根据能力与证据声明，不会仅凭品牌、型号系列、适配器成熟度或 fixture 成功来推断。

## 当前已实现参考适配器

已实现 Merlin 适配器面向运行官方 Asuswrt-Merlin 的华硕网关，要求持久化 `/jffs` 存储、
SSH 访问、已声明的 POSIX 能力，以及受支持的 CPU/运行时组合。受支持固件可能采用精简
BusyBox 用户态，而不是完整 GNU 或新版 BusyBox 选项集。部署器会安装受管安全临时路径
helper，缺少 `base64` 时允许使用 OpenSSL；全新安装不要求固件自带 `mktemp`。运行时路径
使用 ShellCrash/ShellClash 与 Mihomo 兼容运行时。

该实现是项目参考适配器。参考角色只说明它是首个已实现架构路径，不代表已经取得“已验证”
成熟阶段，也不会把支持范围扩展到每个华硕型号、Merlin 构建、运行时版本、服务商或网络。

## 两类独立分类

适配器成熟度描述实现责任与证据：

- 外部集成；
- 实验性适配器；
- 社区维护适配器；或
- 已验证适配器。

目标支持分类描述适配器对某一目标的判断：

- **`supported`**：必需能力与适用证据门禁均已满足；
- **`supported_needs_manual`**：目标适合，但仍须完成明确的人工动作；
- **`accepted_modified`**：操作者明确接受兼容改版基线及其来源/支持风险；
- **`unknown`**：证据不足，无法判断固件、架构、存储、shell、运行时或其他必需能力；
- **`unsupported`**：必需能力缺失，或与适配器边界冲突。

适配器不会因成熟度标签自动取得更宽目标支持声明；某一目标的分类也不会提升适配器成熟度。

## 上游网关与双栈边界

Merlin 适配器只管理华硕网关。上游可以是运营商设备、华为网关或其他路由器，但受管客户端
仍须以华硕 LAN 网关和 DNS 路径为准，华硕 WAN 侧须有可用地址、默认路由、DNS 与 MTU，
并先验证上游直连。双重 NAT、入站端口转发、DDNS 和上游策略不属于本适配器范围。

更换上游构成新的验收事件：应重新检查 WAN 状态、直连、透明路由、DNS 与客户端实际网关。
IPv6 与 IPv4 相互独立；验收时应关闭 IPv6，或单独验证其默认路由、DNS、拦截和出口策略。

## 可选服务依赖配置

应用可能依赖主站之外的多个域名。项目提供
`scripts/configure-shellcrash-service-rules.sh`，默认动作是 `plan`。显式 `apply` 会以原子方式
管理一个已审查配置并记录回滚状态，但不会自动重启或重载 ShellCrash；它要求一个既有服务
策略组，日志不会输出该组名称。内置 OpenAI 配置依据 OpenAI 已发布的网络建议，但不承诺覆盖
未来所有依赖。来自现场证据的 `asus-global-account` 配置刻意保持更窄范围：当账户页面与
OAuth 回调成功、但令牌交换在默认路线被关闭时，它只把 `nomos.asus.com` 交给显式指定的
策略（通常为 `DIRECT`）。它不会把全部 ASUS 流量改为直连，不会改变账户地区，也不认证
所有 Armoury Crate/账户流程。其他服务应使用单独审查的配置，不应写入通用路线恢复策略。

## 公开证据边界

准确的机器可读要求与分类见
[`config/compatibility-matrix.json`](../../config/compatibility-matrix.json)。其中
`field_evidence` 数组有意保持为空，因此其中列出的目标路径保持为 `unknown`。fixture 不是
现场认证：它们只展示脚本面对合成输入时的
离线行为，不代表某个具体路由器、固件构建、服务商或网络的实测结果。

应用前应运行引导式能力检查并审查每一项不匹配。声明的支持级别不保证安全性、可用性或成功。
软路由或端点回退必须保持独立；回退路径成功不能验证路由器路径。

## 未来适配器

新适配器在接纳前应声明能力契约、维护责任、目标支持政策、fixture、备份与回滚行为、不含敏感
信息的诊断、许可边界和双语操作说明。详见[架构](../ARCHITECTURE.md)与[治理](../../GOVERNANCE.zh-CN.md)。
